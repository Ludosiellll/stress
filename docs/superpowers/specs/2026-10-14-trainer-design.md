# Тренажёр к психофизиологическому отбору — дизайн

Дата: 2026-10-14. Статус: на утверждении у пользователя.

## 1. Цель и критерии успеха

**Кто и зачем.** Кандидат готовится к психофизиологическому отбору: компьютерные тесты на скорость реакции, внимание, переключение под стрессом, память и логику. Нужно пройти психологическую диагностику и психофизиологическое обследование с максимальным результатом. Физподготовка вне рамок.

**Что тренируем.** Скорость и стабильность реакции, внимание, переключение внимания при темпе и помехах, оперативная память, логика (числовые ряды, закономерности, КОТ-подобные задания).

**Горизонт.** Ежедневное использование 3–5 месяцев. Дата теста неизвестна, ожидается не раньше чем через 1–2 месяца. Дату можно ввести в любой момент.

**Успех:**
- контрольные диагностики раз в 2 недели показывают рост по каждой способности;
- на реальном тесте формат, темп и помехи не являются неожиданностью; тренировочный уровень превышает уровень теста («сверх нормы»);
- приложение работает без ошибок: ни одного неверного замера, неверного «правильного ответа» в генераторе или потери данных.

**Исходные данные о тестах.** `stress-notes/20_Domain/Test_Battery_Research.md`. Ключевое: точный состав АПК не опубликован, поэтому тренируем **типы** методик постсоветской школы (ПЗМР, СЗМР, РДО, Шульте–Горбов, КОТ, Равен). Стабильность (малый разброс) и отсутствие ошибок ценятся выше рекордной скорости. Работа без перерыва до 2 часов.

**Не делаем:**
- тренировку личностных опросников (СМИЛ, Люшер, «Прогноз») — только справка о формате и о шкалах достоверности;
- имитацию приборных тестов (тремор, теппинг-пластина, координациометр).

## 2. Платформа и стек

- Десктоп Windows: **Tauri 2** (Rust-оболочка: окно, полноэкранный режим, SQLite, файловый экспорт) + **TypeScript + React + Vite**.
- Стимулы рисуются на **Canvas** вне цикла рендера React.
- Тесты: Vitest, fast-check (тесты на свойствах), Playwright (E2E и тайминги), `cargo test` для Rust-части.
- Конкретные версии зависимостей фиксируются в плане реализации после проверки актуальных стабильных релизов.
- Сборка установщика — GitHub Actions на `windows-latest`. Пользователю не нужно ставить Rust.

## 3. Структура репозитория

```
stress/
  src-tauri/        Rust: окно, полноэкранный режим, SQLite (tauri-plugin-sql), экспорт, бэкап.
  src/engine/       Чистый TS без DOM и без I/O: RNG с зерном, генераторы, адаптивный движок,
                    метрики, планировщик, фазы, индекс готовности.
  src/runtime/      Проигрыватель упражнений: планирование стимулов, отрисовка на Canvas,
                    Web Audio, ввод, замер времени, учёт пропущенных кадров.
  src/modules/      Описание каждого модуля: параметры уровня, генерация испытаний, оценка блока,
                    отрисовка (через runtime), инструкция.
  src/ui/           React-экраны.
  src/data/         Интерфейс Repository + реализации: SQLite (Tauri) и in-memory (тесты, веб-превью);
                    очередь синхронизации Supabase.
  content/          Вычитанные вручную банки для словесных заданий (JSON, у каждого пункта флаг reviewed).
  tests/            E2E, тайминги, симуляции.
  docs/             Спецификации и планы.
```

Правило границ: `engine` не импортирует ничего из `runtime`, `ui`, `data`. `modules` зависят от `engine` и интерфейсов `runtime`. UI работает только через `data.Repository` и API модулей.

### Раскладки

Оборудование пользователя: ноутбук (цифрового блока может не быть), клавиатура, мышь, наушники. Тест в центре диагностики, по словам пользователя, проходит «на компьютере», точное устройство ввода неизвестно. Поэтому тренируем и клавиатуру, и мышь.

- **Клавиатура (по умолчанию):** Пробел для одной клавиши; F/J для двух; D/F/J/K для четырёх; S/D/F/J/K/L для шести.
- **Мышь:** левая / правая кнопка для одной или двух альтернатив; клик по цели для модулей с выбором на экране (Шульте–Горбов, варианты ответа в логике).
- **«Пульт»:** стрелки + цифры верхнего ряда 1–6. Это замена цифрового блока Мультипсихометра для ноутбука. Если цифровой блок есть, он работает как эквивалент.
- Раскладка выбирается в настройках. Модуль 16 «Смена раскладки» чередует клавиатуру, мышь и «пульт» по ходу серии.

> **Отклонение 2026-10-15 (F9, `docs/superpowers/specs/2026-10-15-training-fixes-design.md` §4.6):** раскладка из настроек теперь основная, а тренировка и свободная тренировка чередуют её по дням с двумя другими так, что основной достаётся половина любых 28 дней. Диагностика, прогон в формате теста, разминка (T-R65) и последние 3 дня перед тестом идут на основной; настройка «Чередовать раскладки по дням» (по умолчанию включена, из файла не восстанавливается) выключает чередование. В день мыши блок, которому нужно больше двух клавиш, идёт на клавиатуре, а ПЗМР и СЗМР мышью с нормами не сравниваются.

> **Отклонение 2026-10-16 (F9, Р10, T-R64, решение контролёра):** раскладки чередуются по дням тренировок, а не по календарным дням курса. Номер дня — число календарных дней, в которые до сегодняшнего была тренировка или свободная тренировка, плюс 1; диагностика днём тренировки не считается. По календарю курс через день, начатый со второго дня, ни разу не попадал на основную раскладку; теперь основная — ровно половина любых 28 дней тренировок при любом расписании, а последние 3 дня перед тестом по-прежнему на основной.

## 5. Замер времени (критично)

- **Время предъявления стимула** — метка того `requestAnimationFrame`, в котором стимул впервые нарисован. **Время ответа** — `KeyboardEvent.timeStamp` (одна шкала с `performance.now()`). RT = ответ − предъявление.
- **Фальстарт** — нажатие до предъявления или с RT < 100 мс. **Пропуск** — нет ответа в окне.
- **Интервал между сигналами** — случайный, по умолчанию равномерный в [0,5; 2,5] с; на уровнях сверх нормы может сужаться. Стимулы планируются по кадрам, отклонение от заданного интервала логируется.
- **Частота обновления экрана** измеряется при старте сессии. Кадр длиннее 1,5 нормального интервала считается пропущенным. Блок, где пропущенный кадр совпал с предъявлением стимула больше чем в 5 % испытаний, помечается `timing_unreliable` и не влияет на уровень.
- **Повтор клавиши** (key repeat) игнорируется. Учитывается только первое нажатие в окне ответа.
- **Мышь:** время ответа — `MouseEvent.timeStamp` события `mousedown` (не `click`). Курсор на экране упражнения скрыт, кроме модулей с кликом по цели.
- **Ноутбук:** самопроверка и старт сессии проверяют питание (Battery Status API, если доступен) и долю пропущенных кадров. При работе от батареи или нестабильных кадрах выводится предупреждение «подключи зарядку, включи режим максимальной производительности». Для заданий с мышью рекомендуется внешняя мышь, а не тачпад.
- **Звук** — Web Audio, заранее декодированные буферы, запуск по `AudioContext.currentTime`.
- **Самопроверка таймингов** в настройках: частота экрана, разброс кадров, доля пропущенных кадров, оценка погрешности (около 1 кадра). Честная подпись: клавиатура ПК добавляет задержку относительно аппаратной кнопки, нормы ориентировочные.
- **Во время серии** не выполняется никакой сетевой или дисковый ввод-вывод. Запись идёт после блока.

## 6. Адаптивный движок

### 6.1 Уровень

- У каждого модуля есть уровень `L` — вещественное число ≥ 0, без верхней границы.
- Модуль задаёт монотонные кривые `params(L)`: окно ответа, интервалы, число альтернатив, доля no-go, частоту смены правил, помехи и т. п.
- Рычаги включаются последовательно: сначала темп, затем число альтернатив и правил, затем помехи.
- За пределом «нормы теста» кривые продолжаются: окно сжимается асимптотически к физиологическому минимуму (не ниже 150 мс для выбора), а дальше растут нагрузка и помехи.
- Каждый модуль документирует, какой `L` примерно соответствует формату реального теста (`L_norm`).

> **Отклонение 2026-10-15 (F3, `docs/superpowers/specs/2026-10-15-training-fixes-design.md` §3.1):** в шести модулях реакции (ПЗМР, СЗМР, Go/No-Go, Помехоустойчивость, Струп, Переключение) уровень — это нагрузка. Каждые 4 уровня начинается новая полоса `⌊L/4⌋`, и нагрузка накапливается: интервал, помехи, звук, больше цветов и правил, инверсия, длинные блоки. Окно сжимается быстрее, но не бывает уже личного минимума: `windowMs = max(params(L).windowMs, round(1,2 × P80))` по последним 60 чистым попаданиям на этой полосе. Пока попаданий меньше 15, минимум берётся от полосы ниже с множителем полосы; у полосы 0 без истории минимума нет. За последней полосой таблицы идут 4 полосы хвоста с той же нагрузкой, и множитель минимума в них снижается: 1,15, 1,10, 1,05, 1,00. `L_norm` теперь — первый уровень первой полосы тяжелее формата теста: 8 у ПЗМР, СЗМР, Go/No-Go, Помехоустойчивости и Переключения, 12 у Струпа. В диагностике минимума нет: она играет замороженные параметры (§7.3).

### 6.2 Подстройка (блочная взвешенная лестница)

- Блок — 10–20 испытаний (модуль задаёт). Балл блока `s ∈ [0, 1]`: доля испытаний, выполненных правильно и в окне. Фальстарт, ошибка выбора, нажатие на no-go, пропуск и ответ после окна — всё неуспех.
- Цель `p* = 0,80`.
- Шаг: `ΔL = g · (s − p*) / (1 − p*)`, ограничен диапазоном [−2; +3].
  - `g = 2,0` в первых 3 блоках модуля за всё время (калибровка), а также для блока, если предыдущий блок того же модуля в этой сессии имел `s ≥ 0,95`;
  - иначе `g = 1,0`.
  - Сильный игрок поднимается быстро, слабый блок не обваливает уровень.
- **Условие стабильности** (модули с временем реакции): если `s > p*`, но коэффициент вариации RT выше порога модуля `cv_max(L)`, то `ΔL = min(ΔL, 0)`.
- `L` не опускается ниже 0.

> **Отклонение 2026-10-15 (F1, `docs/superpowers/specs/2026-10-15-training-fixes-design.md` §2.1):** шаг уровня, усталость и правило g = 2 в модулях реакции считаются по баллу со штрафом `s = max(0, успехи − неверные − 2·(фальстарты + нажатия на no-go)) / n`: относительно верного ответа в окне опоздание и пропуск стоят 1, неверная клавиша — 2, фальстарт и нажатие на no-go — 3. Раньше ошибка стоила столько же, сколько опоздание, и тот, кто быстро отвечал наугад, поднимался выше ценой лишних ошибок. Балл со штрафом пишется в `blocks.score` и `summaryJson.penalizedScore`; строка «Успешно», `summaryJson.score` и значение Go/No-Go в диагностике остаются долей успехов, поэтому диагностика сравнима со старыми.

> **Отклонение 2026-10-15 (F2, `docs/superpowers/specs/2026-10-15-training-fixes-design.md` §2.2):** условие стабильности учитывает все ответы, а не только попадания в окно (по ним правило срабатывало в 0–2 % блоков): `CV_all` считается по попаданиям и поздним нажатиям до окна + 1000 мс, в модулях с условиями SD берётся внутри условий; провалы — пропуски, ответы дольше 1,5 медианы и нажатия позже окна + 1000 мс. При `s > p*` провалов `max(2, ⌈0,1 · n⌉)` и больше (n — испытания, где нужно нажать) дают `ΔL = min(ΔL, 0)`; если провалов меньше, а `CV_all` выше `cvMax` модуля, то `ΔL = min(ΔL, +0,5)` (поправка F-R1). `cvMax` от уровня не зависит: ПЗМР 0,19, СЗМР 0,22, Go/No-Go 0,205, Помехоустойчивость 0,225, Струп 0,235, Переключение 0,225; у РДО правила нет.

> **Отклонение 2026-10-15 (F6, `docs/superpowers/specs/2026-10-15-training-fixes-design.md` §2.4):** g = 2 и в первом блоке сегмента, который двигает уровень, если его `s ≥ 0,9`: тогда ΔL — от +1 до +2. Блок перегрузки первым не бывает, а прежние правила g = 2 (калибровка, прошлый блок ≥ 0,95) остаются. Так сегмент быстрее возвращается к `L_saved` после сброса на старте (§6.3).

### 6.3 Между сессиями, плато, усталость

- **Старт сессии:** `L_start = max(0, L_saved − 2)`; если модуль не тренировался больше 4 дней — `L_saved − 3`.
- **`L_saved`** — медиана `L` в конце последних 3 сессий модуля. Это защищает от одного случайного дня.
- **Плато:** 5 сессий модуля подряд без нового максимума медианного `L`. Планировщик включает вариант модуля, усиливает чередование и подмешивает перегрузку. Флаг снимается при новом максимуме.
- **Усталость:**
  - внутри сессии медиана RT последних 2 блоков модуля выше медианы первых 2 блоков более чем на 12 % **и** `s` упал на ≥ 0,15 → предложить закончить;
  - последующие блоки помечаются `fatigued` и не меняют `L_saved`.

> **Отклонение 2026-10-15 (F6, `docs/superpowers/specs/2026-10-15-training-fixes-design.md` §2.4):** старт сессии — `L_start = max(0, L_saved − d)`, где d = 1 после перерыва до 4 дней, 2 — после 5–14 дней и 3 — после перерыва больше 14 дней. Со сбросом на 2–3 уровня 72 % блоков СЗМР и Go/No-Go шли ниже `L_saved`, хотя навыки скорости за 1–2 недели почти не забываются. Давность по-прежнему считается по `lastTrainedAt` (W2-R40); модуль, который больше 4 дней шёл только финишером, теперь начинает с `L_saved − 2`, а больше 14 дней — с `L_saved − 3`.

> **Отклонение 2026-10-15 (F5, `docs/superpowers/specs/2026-10-15-training-fixes-design.md` §2.3):** разминка ПЗМР играет все блоки на `max(0, L_saved − 1)` и уровень не меняет: `lAfter = lBefore`, флаг `warmup`. Как и перегрузка, она не входит в `L_saved`, в давность (`lastTrainedAt`), в усталость, в калибровку и в правило g = 2, а в `lifetimeBlocks` входит. Раньше разминка начиналась со сброса и в подводке была короче, поэтому `L_saved` ПЗМР падал перед тестом (13,4 → 12,6 в симуляции аудита), а 81 % блоков ПЗМР шли ниже `L_saved`.

> **Отклонение 2026-10-15 (F3, `docs/superpowers/specs/2026-10-15-training-fixes-design.md` §3.1.4):** блок перегрузки модуля с полосами играет свой уровень L с нагрузкой следующей полосы и окном своей полосы, то есть тем, что было бы в обычном блоке на L. Уровень он не меняет (`lAfter = lBefore`), и в личный минимум окна не входит. Финишер такого модуля идёт на `L_saved`, уровень сегмента не меняется, звук финишера остаётся. Раньше перегрузка шла на `L + 3`, где успех около 0,55 и тренируется угадывание; в симуляции полос (`tests/sim/bands.sim.test.ts`) средний балл перегрузки теперь 0,68–0,82. РДО, таблицы и память по-прежнему идут на `L + 3`.

### 6.4 Числовые ряды

- **Семейства правил:**
  - арифметическая прогрессия;
  - геометрическая прогрессия;
  - разности второго порядка;
  - чередование двух рядов;
  - Фибоначчи-подобные (`a(n) = a(n−1) + a(n−2)` и варианты с коэффициентом);
  - `a·x + b`;
  - степени ± константа;
  - позиционные (`n² + c`, `n·k ± c`);
  - циклы операций (`+a, ×b, +a, ×b`).
- **Сложность задачи** вычисляется из структуры: семейство, число операций, величина чисел, длина показанной части.
- **Проверка единственности:** генерируемый ряд прогоняется через все семейства. Если любое другое семейство с параметрами из допустимых диапазонов точно описывает показанные члены и даёт **другой** следующий член, ряд отбраковывается. Ответ — целое число в допустимых пределах.
- **Рейтинг** по каждому семейству в стиле Эло:
  - ожидание `P = 1 / (1 + 10^((D − R)/400))`;
  - K = 48 для первых 20 задач семейства, далее 32;
  - успех = верно и в пределах лимита времени.
- **Выбор следующей задачи:** семейство с весом, обратным рейтингу (слабые чаще), сложность `D` такая, что `P ≈ 0,75`.

> **Отклонение 2026-10-15 (F12, `docs/superpowers/specs/2026-10-15-training-fixes-design.md` §4.8):** к восьми семействам добавлены шесть (буквенные с ответом-буквой, «прибавить / отнять», простые числа, степени с шагом, растущий множитель, сумма цифр); последние три в тренировку не входят, их даёт только диагностика. Лимит на задачу начинается с 30 с и с `targetD` 1000 сокращается до 8 с: задача берётся около структурной цели `min(STRUCT_D_MAX, 0,5·targetD + 417)`, выше неё не больше чем на 25, а лимит доводит D_eff до `targetD`. Пробел пропускает задачу, она засчитывается как неверная.

### 6.5 Матрицы (W3)

- Матрица 3×3, атрибуты: форма, количество, размер, поворот, заливка.
- Правила по строкам: константа, прогрессия, распределение трёх значений, сложение/вычитание.
- 8 вариантов ответа. Дистракторы отличаются от ответа ровно одним атрибутом.
- Проверка: ровно один вариант удовлетворяет всем правилам.
- Рейтинг по правилам — как в §6.4.

## 7. Программа

### 7.1 Ежедневная сессия (30–40 мин, 5–6 дней в неделю)

1. Разминка ПЗМР, 2 мин. Это и замер состояния дня.
2. Реакция, около 10 мин: 2 модуля.
3. Внимание и память, около 10 мин: 2 модуля.
4. Логика, около 10 мин.
5. Финишер-перегрузка, 3–5 мин.
6. Самочувствие: часы сна, кофеин (да/нет), самочувствие 1–5.

> **Отклонение 2026-10-15 (F5, `docs/superpowers/specs/2026-10-15-training-fixes-design.md` §2.3):** разминка (п. 1) идёт на фиксированном уровне `L_saved − 1` (§6.3), а ПЗМР входит в пул слотов реакции (п. 2) последним: при равном приоритете его берут после СЗМР, Go/No-Go, РДО и Помехоустойчивости. Уровень ПЗМР теперь двигает только этот слот. Замер состояния дня показан в итоге каждого блока разминки строкой «Форма дня»: медиана и SD (без выбросов за 3 SD) чистых попаданий сегодняшних разминок против медианы дневных медиан и дневных SD за 14 прошлых дней на той же полосе `⌊L/4⌋`. Нужно не меньше 3 таких дней. Медиана «как обычно», если разница не больше max(10 мс, 4 %). В «Прогрессе» есть график дневной медианы разминки за 30 дней.

> **Отклонение 2026-10-15 (F4, `docs/superpowers/specs/2026-10-15-training-fixes-design.md` §3.2):** с 15-го дня курса дважды в неделю сессия начинается с прогона в формате теста, до разминки: один непрерывный блок на параметрах диагностики (§7.3), 5 пробных и затем ПЗМР 50, СЗМР 70, Go/No-Go 60 или РДО 50 сигналов, по кругу. Прогон ставится, если за последние 7 дней, включая сегодня, их было меньше двух, а последний был 3 и больше дней назад; в подводке тоже. Он занимает один слот реакции (п. 2), его модуль в этот день в другие слоты не попадает, а в день прогона ПЗМР нет разминки. Уровень прогон не меняет и в `L_saved`, давность, усталость и личный минимум окна не входит. Итог сравнивает среднее (у РДО — отклонение), SD, ошибки и фальстарты с лучшими значениями прошлых прогонов того же формата; в «Прогрессе» по каждому формату есть графики и таблица лучших результатов.

> **Отклонение 2026-10-15 (F15, `docs/superpowers/specs/2026-10-15-training-fixes-design.md` §4.3):** после испытания в ПЗМР, СЗМР, Go/No-Go, Струпе, Переключении и Помехоустойчивости на 150 мс появляется «рано» (фальстарт) или «ошибка» (неверная клавиша, нажатие на no-go): в «Базе» после каждого испытания, в «Развитии» — примерно после половины, в «Перегрузке» и «Подводке» — никогда. Свободная тренировка берёт фазу дня. В разминке, прогонах в формате теста, РДО и диагностике отметок нет, и расписание стимулов от отметки не зависит.

> **Отклонение 2026-10-14 (W2-R12):** финишер (п. 5) есть не в каждой сессии. В фазе «База» его нет: она отведена калибровке модулей. Финишер появляется в «Развитии» (3 мин) и идёт в «Перегрузке» (5 мин). В «Подводке» финишера нет. Цена: первые 14 дней и дни калибровки новых модулей проходят без финишера.

**Планировщик выбирает модули по приоритету** = давность + слабость (ниже процентиль собственного прогресса) + флаг плато. Модули из одной группы чередуются между днями. В W1 доступны только модули W1, состав сессии подстраивается под них.

> **Отклонение 2026-10-15 (W2-R40):** блоки перегрузки (финишер и блоки плато) входят в число блоков модуля (`lifetimeBlocks`), но давность (`lastTrainedAt`) считается только по обычным блокам. Если бы финишер обновлял давность, его модуль на следующий день выглядел бы только что пройденным, уступал обычный слот и снова попадал в финишер. В симуляции на 120 дней с модулями на уровне нормы «Переключение правил» после 17-го дня больше не получало обычных блоков (перерыв 104 дня), а его `L_saved` не менялся. По этой же давности работает правило §6.3 «не тренировался больше 4 дней»: модуль, который больше 4 дней шёл только финишером, начинает с `L_saved − 3`. Старая история пересчитывается по новому правилу при запуске.

### 7.2 Фазы

| Фаза | Когда | Особенности |
|---|---|---|
| База | первые 14 дней или пока каждый доступный модуль не пройден ≥ 3 раз | стартовая диагностика, калибровка |
| Развитие | после базы | полная адаптивность, упор на слабые места |
| Перегрузка | ≤ 28 дней до даты теста или с 60-го дня, если дата не задана | больше финишера, звук, длинные прогоны, «День теста» раз в неделю |
| Подводка | ≤ 9 дней до даты | объём −40 %, сессии в утреннее время теста, 2 генеральные репетиции, напоминания о сне, без новых модулей |

### 7.3 Контрольная диагностика (каждые 14 дней)

- Неадаптивна, фиксирует формат: одинаковые параметры, длина и порядок.
- Задания разные, но генерируются из фиксированного набора зёрен равной сложности.
- Состав W1: ПЗМР 50, СЗМР (2 клавиши) 70, Go/No-Go 60, РДО 50, Шульте–Горбов (3 задания), числовые ряды 20 задач за 10 мин.
- Модули последующих волн добавляются в диагностику по мере появления. Старые диагностики остаются сравнимыми по общим тестам.

> **Отклонение 2026-10-15 (П0, `docs/superpowers/specs/2026-10-15-training-fixes-design.md` §2.0):** параметры диагностики реакции заморожены таблицей `DIAGNOSTIC_PARAMS` (`src/modules/reaction/diagnosticParams.ts`): в ней записаны значения `params(fixedL)` версии 0.2.0, а уровни и объёмы сегментов — в `DIAGNOSTIC_VOLUME`. Формат реакционных сегментов диагностики больше не зависит от `params(L)`: изменения тренировки 0.3.0 его не трогают. `fixedL` по-прежнему пишется в историю как уровень блока.

> **Отклонение 2026-10-15 (F11, `docs/superpowers/specs/2026-10-15-training-fixes-design.md` §4.2):** в диагностике каждое задание можно один раз перезапустить клавишей Esc (уведомление «Блок перезапущен. В диагностике это можно сделать один раз за задание.»); следующий Esc блок не останавливает, а показывает подсказку «Перезапуск уже использован — доведи задание до конца.», и перезапуск после потери фокуса лимит не тратит. Перезапуски записываются в `resultsJson.restarts` и в следующий сохранённый блок (`summaryJson.restarts`), а в таблице итогов колонка «Перезапуск» показывает «да» у модуля, задание которого перезапускали клавишей Esc, и «фокус» (или «фокус ×2») за перезапуски после потери фокуса; при обоих — «да; фокус» (T-R57). В тренировке Esc после 30 % блока засчитывает его как s = 0 (уровень — `nextLevel(L, s = 0)`, если блок двигает уровень, флаг `discarded`); Esc раньше, потеря фокуса и ошибка отрисовки перезапускают блок бесплатно.

> **Отклонение 2026-10-15 (F10, `docs/superpowers/specs/2026-10-15-training-fixes-design.md` §4.5):** три задания Горбова идут на одной таблице, как на настоящем тесте: в диагностике она строится из зерна попытки задания 1 (перезапуск задания 1 даёт новую таблицу, 2–3 — ту же), в тренировке так же идут блоки 0–2 сегмента, без перемешивания, кроме перегрузки. В `resultsJson` пишется `gorbovOneTable: true`; базу Π и сравнение с прошлой диагностикой дают только диагностики того же формата, а старые результаты Горбова помечены «(3 разные таблицы, до 0.3.0)» и в итогах не сравниваются.

> **Отклонение 2026-10-15 (F12, `docs/superpowers/specs/2026-10-15-training-fixes-design.md` §4.8):** числовые ряды диагностики — одна из шести постоянных форм v2, каждая следующая после той, что сыграла прошлая диагностика (перезапуск задания тоже берёт следующую): 20 задач, 11 тренировочных семейств по разу и три отложенных по три, поэтому «Логика» больше не меряет заученные в тренировке шаблоны. В `resultsJson` пишется `seriesForm: 'v2'`; базу «Логики» и сравнение с прошлой диагностикой дают только диагностики того же формата (v2 или прежние ряды). Первая диагностика v2 откладывает «Логику» до следующей, а изменение рядов при разных формах в итогах — «несравнимо: формат изменён в 0.3.0».

### 7.4 «День теста» (W3)

- Полная имитация:
  - инструкция перед каждым тестом;
  - 5–7 пробных испытаний, которые не засчитываются;
  - стандартные форматы в фиксированном порядке;
  - во время теста без обратной связи;
  - 90–120 мин с перерывом 10 мин после 2 часов (если доходит);
  - опционально фон кабинета в наушниках.
- Отчёт сравнивает с нормами из исследования (с пометкой «ориентировочно») и с собственной историей.

### 7.5 Индекс готовности

- По каждой способности (реакция, внимание, переключение, память, логика) и общий, 0–100.
- **Источник** — последняя контрольная диагностика.
- **Перевод в баллы.** Каждый показатель переводится через таблицу полос нормы в балл: низкий 20, ниже среднего 40, средний 60, выше среднего 80, высокий 100, с линейной интерполяцией внутри полосы. Где опубликованной нормы нет, используется собственная стартовая диагностика как «средний».
- Полосы каждого показателя хранятся в одном файле конфигурации с указанием источника.

> **Отклонение 2026-10-14 (W2-R31):** показатель, для которого последняя диагностика сама служит базой, получает 60 баллов при любом результате. Поэтому он не входит ни в свою способность, ни в общий индекс до следующей диагностики, если у других показателей база более ранняя. Без этого правила первая диагностика 0.2.0 после диагностик 0.1.0 опускала общий индекс примерно с 96 (с 2026-10-15 — 97) до 81 при неизменных результатах W1. Самая первая диагностика по-прежнему считает все показатели с собственной базой — по 60, как в W1. Главная, «Прогресс» и экран итогов диагностики пишут: «Новые показатели войдут в индекс со следующей диагностики.» Цена: новые способности учитываются на одну диагностику позже.

> **Отклонение 2026-10-15 (оценка результатов, `docs/superpowers/specs/2026-10-15-assessment-design.md` §4):** Π таблицы Горбова в способности «Переключение» считается от собственной базы, как разности: `diffScore(Π, Π₀, 20 с)`; первая диагностика даёт 60, а впервые измеренная Π ждёт следующей диагностики (W2-R31). Полосы P и Π удалены: их не нашлось ни в одном источнике. V остаётся на бумажной шкале как ориентир. Старые диагностики пересчитываются по новому правилу; индекс может сдвинуться, это ожидаемо.

> **Отклонение 2026-10-15 (F7, `docs/superpowers/specs/2026-10-15-training-fixes-design.md` §4.1):** в «Реакцию» входят ещё две части — разброс ПЗМР и СЗМР: SD чистых попаданий без выбросов за 3 SD, от собственной базы, `sdScore(v, v₀) = clamp(60 + 40·(v₀ − v)/(0,6·v₀), 0, 100)`. Шкала 0,6 вместо 0,25, потому что SD 50–70 испытаний шумит на 16–23 %: без реального изменения часть сдвигается не больше чем на 23 балла SD. У диагностик до 0.3.0 разброса нет, и первая диагностика с ним ждёт следующей (W2-R31). IQR, фальстарты, неверные клавиши, нажатия на no-go, пропуски и «рано», «поздно», смещение РДО только показываются строками под таблицей итогов и в индекс не входят.

### 7.6 Наблюдения о самочувствии (W4)

- Пример: «после сна < 6 ч медиана ПЗМР выше на N мс».
- Показываются только при ≥ 10 наблюдениях в каждой группе и разнице больше стандартной ошибки ×2.

### 8.2 Синхронизация Supabase (отложена)

> **Решение 2026-10-14:** синхронизация отложена. Бесплатный тариф Supabase допускает два активных проекта на владельца, оба заняты другими проектами пользователя. Вместо неё в W2 делается восстановление из файла экспорта (слияние по UUID, бэкап перед записью). Раздел ниже остаётся описанием на будущее.


- Supabase — **только синхронизация и бэкап**. Приложение полностью работает без сети и без аккаунта.
- Вход по email (одноразовый код). Те же таблицы истории с колонкой `user_id` и RLS «только свои строки». Кэши и `settings` не синхронизируются. `settings` — локальные, кроме даты теста и раскладки.
- Отправка: после завершения сессии и при запуске приложения — строки из `sync_queue`, батчами, upsert по UUID (идемпотентно). Ошибка сети → повтор с экспоненциальной паузой. Во время серии синхронизация не запускается.
- Загрузка: на новом устройстве или после переустановки скачиваются все строки пользователя, затем `rebuildCaches()`.
- Ключи Supabase не хранятся в репозитории. URL и публичный ключ задаются в настройках или переменными сборки. Публичный (anon) ключ допустим в клиенте только при включённом RLS.
- Перед реализацией проверить доступность Supabase из страны пользователя. Если сервис недоступен, синхронизация остаётся выключенной, а резервное копирование идёт через экспорт.

## 9. Интерфейс

- Русский язык, управление полностью с клавиатуры.
- **Экран упражнения:** полноэкранный, нейтральный тёмно-серый фон, крупные контрастные стимулы, ничего лишнего во время серии. Перед модулем — инструкция и пример.
- **Главная:** план на сегодня, кнопка «Начать», индекс готовности, серия дней, дней до теста.
- **После блока:** уровень, изменения параметров («окно ответа 520 → 480 мс») и причина, SD, типы ошибок.
- **Прогресс:** графики контрольных диагностик, кривые `L` по модулям, история сессий.

> **Отклонение 2026-10-15 (F7, `docs/superpowers/specs/2026-10-15-training-fixes-design.md` §4.1):** у графиков диагностик, общего индекса готовности, прогонов в формате теста и «формы дня» есть полоса шума: прямая наименьших квадратов по последним ≤ 6 точкам ± 2σ̂, где σ̂ — по последовательным разностям этих точек. Под графиком строка «Тренд: −12 мс за 5 недель — лучше (шум ±3 мс)», а если изменение не больше 2σ̂ — «в пределах шума». Пока точек меньше 3, полосы нет, и строка говорит, когда она появится.

- **Режимы:** свободная тренировка модуля, контрольная диагностика, «День теста» (W3).
- **Настройки:** раскладка, звук и громкость помех, дата теста, Supabase, экспорт, самопроверка таймингов, сохранение отчёта об ошибке.
- **Стиль:** строгий, функциональный, без декоративных градиентов. Подписи честные: «норма ориентировочная», «блок помечен: усталость», «замер ненадёжен».

## 10. Обработка ошибок

- Глобальный перехват исключений. Журнал ошибок пишется локально с ротацией.
- Кнопка «Сохранить отчёт»: журнал + версия + сведения о таймингах, без личных данных самочувствия.
- Сбой во время блока: блок отбрасывается целиком, сессия продолжается. Сессия, прерванная закрытием окна, сохраняется как неполная.
- Ошибка записи в БД: повтор, затем сообщение пользователю. Данные блока держатся в памяти до успешной записи.

## 11. Качество и проверка

1. **TDD для всего `engine` и `modules`.** Строгий TypeScript (`strict`, `noUncheckedIndexedAccess`), ESLint. Покрытие `engine` ≥ 95 % строк и ветвей — порог в CI.
2. **Тесты на свойствах** (fast-check, ≥ 1000 прогонов на свойство):
   - таблицы Шульте/Горбова содержат каждое число ровно один раз и правильные цвета;
   - каждый числовой ряд имеет единственный ответ по библиотеке правил (§6.4);
   - каждая матрица имеет ровно один верный вариант;
   - одно зерно → одинаковое задание;
   - `params(L)` монотонны и конечны для `L ∈ [0; 1000]`;
   - `ΔL` в пределах ограничений;
   - `rebuildCaches()` эквивалентен пошаговому обновлению.
3. **Симуляция адаптивного движка.** Синтетические игроки с заданной функцией успеха от `L`, сотни сессий:
   - сходимость к `s ≈ 0,80 ± 0,05`;
   - сверхсильный игрок не упирается в потолок;
   - у растущего игрока `L` растёт;
   - один плохой блок не снижает `L_saved`.
4. **Тайминги и E2E** (Playwright на веб-сборке с in-memory репозиторием):
   - нажатия в известные моменты → RT совпадает с точностью до 1 кадра;
   - фальстарты и повтор клавиши обрабатываются верно;
   - полный проход: сессия, диагностика, настройки, экспорт, синхронизация с подменённым Supabase;
   - скриншоты экранов для визуальной проверки.
5. **Rust:** `cargo test` для миграций и бэкапа. Миграции проверяются на заранее сохранённой БД предыдущей версии.
6. **CI на каждый push:** lint, typecheck, unit + свойства + симуляция, E2E, сборка установщика Windows.
7. **Перед релизом:** независимое код-ревью отдельным агентом, ручная проверка установщика пользователем, запись в CHANGELOG.

## 12. Порядок реализации

- **W1 (MVP):** каркас Tauri + React; engine (RNG, адаптивный движок, метрики); runtime (тайминги, Canvas, ввод); модули ПЗМР, СЗМР, Go/No-Go, РДО, Шульте–Горбов, числовые ряды; SQLite; экраны Главная / Сессия / После блока / Прогресс / Настройки; контрольная диагностика W1; самопроверка таймингов; CI и сборка установщика.
- **W2:** помехоустойчивость, Струп, переключение правил, память, звук и стрессоры в наушниках, восстановление из файла экспорта (Supabase-синхронизация отложена, см. §8.2), полный планировщик и фазы.
- **W3:** матрицы, КОТ-блок с банком слов, корректурная проба, Крепелин, двойная задача, смена раскладки, «День теста».
- **W4:** «Красный квадрат», наблюдения о самочувствии, полировка.

Каждая волна получает свой план реализации. Первый план покрывает W1.
