# Оценка результатов: ступени, нормы, история — дизайн (0.3.0)

Дата: 2026-10-15. Основной дизайн тренажёра: `docs/superpowers/specs/2026-10-14-trainer-design.md` (дальше — «основная спека»).

**Решения принимал агент.** Пользователь дал общее поручение («вопросов не задавай, решай сам») и выбрал три вещи:
- оценивать по трём шкалам сразу: своя история, уровень и сырые цифры;
- показывать оценку после каждого блока, в «Прогрессе» и в итогах диагностики (в сравнении с прошлой);
- таблицы ступеней брать из опубликованных норм там, где они внятные, а иначе из целей тренажёра с честной подписью.

Остальное решено здесь. Каждое решение можно пересмотреть.

## 1. Зачем

Сейчас итог блока показывает цифры: время, ошибки, уровень, что изменилось. Но он не говорит, хорошо это или плохо и к чему стремиться. Пользователь хочет сразу видеть:
- где он на шкале;
- что делал раньше в этом же блоке;
- сколько нужно для следующей ступени.

## 2. Три шкалы

### 2.1 Ступень тренажёра (по уровню)

Шкала есть у всех модулей с уровнем, то есть у всех, кроме числовых рядов. За опору берётся `L_norm` — уровень, примерно соответствующий формату реального теста (основная спека §6.1).

| Ступень | Условие | Название |
|---|---|---|
| 1 | `L < L_norm / 2` | начальная |
| 2 | `L_norm / 2 ≤ L < L_norm` | на подходе к формату теста |
| 3 | `L_norm ≤ L < L_norm + 5` | формат теста |
| 4 | `L_norm + 5 ≤ L < L_norm + 10` | сверх нормы |
| 5, 6, … | `L ≥ L_norm + 5·(n − 3)` | далеко сверх нормы |

- **Без потолка.** Начиная с 5-й, каждая следующая ступень на 5 уровней выше предыдущей.
- **Цель.** Ближайшая ступень выше: её уровень, сколько до неё уровней и что на ней изменится. «Что изменится» — это строки `describeChanges(module, L, L_next)`, например «Окно ответа: 646 → 477 мс», «Цветов: 3 → 4». Так цель тренажёра выражена в сырых требованиях: в таблицах Горбова на уровне 17 нужно уложиться в 29 с, и таблица перемешивается.
- **По какому уровню считать.** Для обычного блока — уровень после блока (`lAfter`). Блок перегрузки ступень не меняет: показывается сыгранный уровень с пометкой «перегрузка».

**Числовые ряды** (уровня нет, есть рейтинг Эло по 8 семействам):
- Опора — рейтинг `R_format = 1376`. При нём задачи формата диагностики (D от 900 до 1470, в среднем 1185) решаются в среднем с вероятностью 0,75: `1185 + 190,85`, формула `expectedScore` из `engine/elo.ts`.
- Ступени ограничены по среднему рейтингу семейств:
  - 1: `< 1100`;
  - 2: `1100…1376`;
  - 3: `1376…1576`;
  - 4: `1576…1776`;
  - далее через каждые 200.
- Цель — рейтинг следующей ступени.

### 2.2 Нормы (ориентир)

Сырой показатель блока сравнивается с опубликованной нормой, где она есть. Источники, рейтинги надёжности и расчёт полос — в заметке исследования норм (не в репозитории). Здесь только то, что идёт в приложение.

Полосы: «низкий», «ниже среднего», «средний», «выше среднего», «высокий». Подпись всегда «ориентировочно», с источником и условием.

| Модуль, показатель | Полосы (лучше → хуже) | Источник, условие | Когда применять |
|---|---|---|---|
| ПЗМР, среднее время, мс | < 225 / 225–234 / 234–267 / 267–277 / > 277 | Мальцев 2026, юноши 18–21, аппаратная кнопка, процентили P10/P25/P75/P90 + 30 мс на клавиатуру | всегда (тренировка и диагностика) |
| ПЗМР, SD, мс | < 37 / 37–45 / 45–68 / 68–87 / > 87 | то же, без поправки | всегда |
| СЗМР, среднее время, мс | < 326 / 326–342 / 342–382 / 382–412 / > 412 | Мальцев 2026, выбор из 2, + 30 мс | только 2 цвета на 2 клавиши (`L < 8`, диагностика) |
| Горбов, время простого задания (чёрные ↑ или красные ↓), с | ≤ 29 / 30–37 / 38–50 / 51–60 / ≥ 61 | 5-балльная шкала V, бумажный вариант, первоисточник не указан | задания 1 и 2 |
| Горбов, чередование P = t3, с | ≤ 130 / 131–170 / 171–260 / 261–320 / ≥ 321 | та же шкала | задание 3 |
| Объём памяти на цифры | ≥ 9 / 8 / 7 / 6 / ≤ 5 | Woods 2011, молодые взрослые 7,1–7,4 ± 0,9, слуховое предъявление | протокол объёма (диагностика); в тренировке — длина ряда в режиме цифр, если точных ответов ≥ 4 из 6 |

**Подсказки** (одной строкой, без полос):
- **Струп, интерференция:** у молодых взрослых обычно 60–90 мс; меньше 40 — выше среднего, больше 150 — ниже среднего (Rouder 2023, клавиатура).
- **Переключение правил, цена переключения:** при короткой подсказке обычно около 60 ± 70 мс (Stasenko 2017).
- **Go/No-Go, ошибки на no-go:** у студентов 7–21 % при 30 % no-go, в зависимости от темпа (Hasegawa 2020).
- **Шульте 5×5:** традиционная норма взрослых на бумаге 40–50 с, хороший результат 25–30 с.

У РДО, разности в «Помехоустойчивости» и числовых рядов нормы нет. Там только ступень и история.

**Поправка на клавиатуру** — постоянные +30 мс (USB-клавиатура добавляет 20–40 мс, Neath 2011, Plant). Подпись: «норма для аппаратной кнопки + 30 мс на клавиатуру».

### 2.3 История этого блока

**Вариант блока** — то, с чем честно сравнивать:
- модуль;
- у Горбова — задание (1, 2 или 3);
- у Шульте — размер сетки;
- у памяти — режим.

**Какие блоки берутся:**
- только тренировка и свободная тренировка;
- без блоков с отметкой «замер ненадёжен» и без блоков перегрузки;
- блоки с отметкой «усталость» берутся.

**Ключевой показатель** (одно число на блок):

| Модуль | Показатель | Лучше |
|---|---|---|
| ПЗМР, СЗМР, Go/No-Go | среднее время, мс | меньше |
| РДО | средняя ошибка по модулю, мс | меньше |
| Горбов, Шульте | время, с; не закончено — нет числа | меньше |
| Струп | интерференция, мс (`shownCost`) | меньше |
| Переключение правил | цена переключения, мс | меньше |
| Помехоустойчивость | разница с помехами и без, мс | меньше |
| Память | точных ответов, % (и длина ряда) | больше |
| Числовые ряды | верно из N, % | больше |

**Строка истории:** «Раньше в этом блоке: прошлый раз 48,2 с (ур. 11) · лучший 41,0 с · в среднем за 7 дней 45,3 с». Если блок лучше прошлого или лучше всех, это отмечается: «новый лучший результат».

Без истории (первый блок варианта) строка звучит так: «Первый такой блок — будет с чем сравнивать».

> **Уточнение 2026-10-15 (план, решение О2):** «новый лучший результат» ставится, только если блок строго лучше всех прежних. Если он лучше прошлого раза, но не лучшего, строка заканчивается на « — лучше прошлого раза». Значения сравниваются в том округлении, в каком показаны.

> **Уточнение 2026-10-15 (финальная волна, FW4):** хвост « — будет с чем сравнивать» получает только блок, который сам идёт в историю. У блока перегрузки, блока с ненадёжным замером, незаконченной таблицы и блока без ключевого показателя строка — просто «Первый такой блок»: следующий блок с ним сравнивать не будут.

## 3. Где показывается

### 3.1 После каждого блока

На экране итога блока появляется раздел «Оценка», три–пять строк:
```
Ступень 3 из 5+ — формат теста (уровень 13,5; формат теста — 12)
До ступени 4 «сверх нормы»: уровень 17 (+3,5). Там: лимит 44 → 29 с; перемешивание каждые 9 верных
Норма (ориентир): 44,0 с — средний; выше среднего — до 37 с. Бумажная методика, источник не указан
Раньше в этом блоке: прошлый раз 48,2 с (ур. 11) · лучший 41,0 с · в среднем за 7 дней 45,3 с
```

В диагностике ступени нет (уровни там фиксированные). Там показываются норма и прошлая диагностика (3.3).

> **Уточнение 2026-10-15 (финальная волна, FW1):** в итоге блока РДО вместо строки «Средняя ошибка: ±N мс» теперь две. «Средняя ошибка по модулю: N мс» — то число, которое сравнивают история блока и итоги диагностики. «Смещение: ±N мс» — ошибка со знаком, с пояснением «(запаздываешь)» или «(торопишься)»; при нуле — «Смещение: 0 мс».

### 3.2 «Прогресс»

Новый раздел вверху — «Оценка по модулям», таблица по всем модулям:
- **Модуль.**
- **Ступень:** название, уровень и `L_norm`. У рядов — рейтинг и `R_format`.
- **Последний и лучший за 30 дней:** ключевой показатель основного варианта. У Горбова — чередование, у памяти — режим цифр, у Шульте — самая крупная пройденная сетка.
- **Ориентир:** полоса нормы для последнего результата, если норма есть.
- **Цель:** уровень следующей ступени и сколько до неё.

Модули без истории показываются с прочерком и «ещё не тренировался».

### 3.3 Итоги диагностики

К таблице результатов на экране «Сессия завершена» добавляются:
- **Прошлая диагностика:** значение из предыдущей диагностики по дате (`at`, W2-R33), её номер и дата.
- **Изменение:** разность со знаком и пометкой «лучше» или «хуже» с учётом направления показателя. Пороги: изменение меньше 2 % или 5 мс считается «без изменений».
- **Ориентир:** полоса нормы, где норма есть (ПЗМР, СЗМР, Горбов, объём памяти).
- **Индекс готовности:** «Индекс: 72 (прошлый — 65)». Оба значения считаются той же функцией `readinessOfLatest`.

Первая диагностика показывает «Первая диагностика — сравнивать пока не с чем».

ПЗМР и СЗМР в диагностике сейчас хранят медиану, а нормы даны по среднему. Поэтому в `DiagnosticMetrics` добавляются `pzmrMeanRt` и `szmrMeanRt`, которые равны `null` в старых записях. Ориентир по ним показывается только при наличии значения.

## 4. Индекс готовности: полосы Горбова

**Что выяснилось.** Полосы `BAND_GORBOV_P` и `BAND_GORBOV_PI` в `engine/readiness.ts` ни в одном источнике не нашлись. Похоже, это опубликованная шкала, поделённая на 3 и примерно на 5. Полоса V совпадает с распространённой бумажной шкалой (без первоисточника).

**Отклонение от основной спеки §7.5, дата 2026-10-15:**
- **Pi** в способности «Переключение» считается от собственной базы, как разности: `diffScore(Pi, Pi0, 20 000 мс)`. 20 с — оценка агента: обычный разброс Pi в кликовой версии. Первая диагностика даёт 60.
- **V** остаётся на бумажной шкале как ориентир (рейтинг C/B).
- **`BAND_GORBOV_P`** удаляется: он нигде не используется.
- **Старые диагностики** пересчитываются по новому правилу. Индекс может сдвинуться — это исправление, а не регресс.

## 5. Устройство

- `src/engine/norms.ts`, чистые данные и функции:
  - таблицы полос (значение порогов, направление, источник, рейтинг, подпись, условие);
  - `gradeByBands(value, table)` → `{ band: 1..5, label, nextLabel, toNext }`.
- `src/engine/levelSteps.ts`:
  - `levelStep(L, Lnorm)` → `{ step, name, nextStepL }`;
  - `ratingStep(R)` для рядов.
- `src/session/blockHistory.ts`, чистая:
  - `buildBlockHistory(blocks, sessions)` → карта «вариант → записи `{ at, value, L }`»;
  - `variantOf(...)`, `keyMetric(...)` с защитным разбором `summaryJson` (импортированные строки);
  - `historyStats(entries, now)` → прошлый, лучший, среднее за 7 дней.
- `src/session/assessment.ts`, чистая (может импортировать модули): `assessBlock(...)` → `BlockAssessment` (ступень, цель с `describeChanges`, норма или подсказка, история).
- **Контроллер:**
  - при старте сессии загружает `listBlocks()` и `listSessions()` и строит историю;
  - ошибка загрузки пишется в журнал, а сессия идёт без истории;
  - после каждого завершённого блока добавляет его в историю.
  - `BlockSummaryView` получает поле `assessment?`.
- **Диагностика:**
  - шаг `done` получает `previous: { number, at, metrics } | null` и `readinessPrevious`;
  - контроллер уже читает прошлые диагностики, поэтому новых чтений не нужно.
- **UI:** раздел «Оценка» в `BlockSummary`, таблица «Оценка по модулям» в «Прогрессе» (`progressModel` + `Progress.tsx`), колонки сравнения в `Done`.
- **Данные:** миграции нет. История строится из `blocks` и `sessions`. `DiagnosticMetrics` хранится в JSON, а новые поля в старых записях равны `null`.

## 6. Проверка

- Юнит-тесты на каждую функцию, движок и модули с покрытием 100 %:
  - полосы на границах;
  - ступени, включая без потолка, `L = 0`, `L_norm` у рядов;
  - история: варианты, исключения, повреждённый `summaryJson`, пустая история;
  - цели через `describeChanges`;
  - `pzmrMeanRt` в диагностике;
  - пересчёт Pi.
- Тесты UI: раздел «Оценка» с историей и без неё, «Прогресс» с модулем без истории, `Done` с прошлой диагностикой и без неё.
- e2e: после блока свободной тренировки виден раздел «Оценка», после второй диагностики — колонка «Прошлая».
- Снимки экранов новых разделов и визуальная проверка.
- Руководство пользователя: раздел «Оценка результатов» со ступенями, нормами (с источниками) и поправкой на клавиатуру.
