> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Рабочий десктопный тренажёр (Windows) с модулями ПЗМР, СЗМР, Go/No-Go, РДО, Шульте–Горбов/Шульте, числовые ряды, адаптивным движком, локальной БД, ежедневной сессией, контрольной диагностикой, прогрессом и установщиком из CI.

**Architecture:**
- Вся логика — чистый TypeScript в `src/engine` и `src/modules`, покрытый unit-тестами, тестами на свойствах и симуляциями.
- `src/runtime` проигрывает блоки по кадрам через внедряемые часы и рендерер, поэтому тайминги тестируются без браузера.
- Результат блока считается чистой функцией из «таймлайна» (метки предъявлений и нажатий).
- UI на React работает через `SessionController` и интерфейс `Repository`.
- Tauri даёт окно, SQLite (`tauri-plugin-sql`), бэкап и экспорт.

## Review Focus

1. **Окно теряет фокус посреди блока** (Alt+Tab, уведомление Windows). Ожидание: блок отбрасывается и повторяется, уровень не меняется, данные блока не пишутся. Тест — Task 10 (`aborts on visibility/blur`) и Task 13 (`discardBlock keeps level and writes nothing`).
2. **Зажатая клавиша и несколько нажатий подряд или одновременно.** Ожидание: считается только первое нажатие в окне, автоповтор игнорируется. Тест — Task 6 (`only first press in window counts`) и Task 10 (`ignores key repeat`).
3. **Приложение закрыли посреди сессии.** Ожидание: пройденные блоки сохранены, уровни учтены, сессия видна как неполная, следующий запуск работает. Тест — Task 13 (`blocks persist before session end`) и Task 12 (`derive handles unfinished session`).
4. **Системные часы «назад» или дата теста в прошлом.** Ожидание: дни с прошлой тренировки не бывают отрицательными, «дней до теста» не бывает меньше 0, планировщик не падает. Тест — Task 11 (`negative day gaps clamp to 0`).
5. **Ввод ответа в числовых рядах:** пробелы, юникодный минус «−», «–», ведущие нули, пустая строка, буквы. Ожидание: числа распознаются, пустой или невалидный ввод не засчитывается как ответ. Тест — Task 9 (`parseAnswer`).

## Справочник параметров (решения, на которые ссылаются задачи)

### Адаптивный движок (§6.2–6.3)

- `TARGET = 0.8`.
- Шаг: `ΔL = g · (s − 0.8) / 0.2`, ограничен диапазоном [−2, +3]. Итоговый `L` не ниже 0.
- `g = 2` в двух случаях:
  - блок модуля входит в первые 3 за всё время (`lifetimeBlocks < 3`, флаг блока `calibration`);
  - предыдущий блок того же модуля в этой сессии имел `s ≥ 0.95`.
  - Иначе `g = 1`.
- Условие стабильности: если `s > 0.8` и `cvMax(L) !== null` и `cvRt > cvMax(L)`, то `ΔL = min(ΔL, 0)`.
- Блок с флагом `timing_unreliable` даёт `ΔL = 0` и не учитывается в `sessionEndLevels`.
- Старт сессии: `L_start = max(0, L_saved − (daysSince > 4 ? 3 : 2))`. Отрицательный `daysSince` приравнивается к 0.
- Уровень на конец сессии — `L_after` последнего блока модуля в сессии без флагов `fatigued` и `timing_unreliable`. `L_saved` = медиана трёх последних таких значений (или меньшего числа, если сессий меньше; если их нет — 0).
- Плато: среди значений `L_saved` после каждой сессии было ≥ 5 сессий с последнего строгого нового максимума.
- Усталость (только реакционные модули): нужно ≥ 4 блока модуля в сессии без флагов. Условие: `median(RT hits последних 2 блоков) > 1.12 · median(RT hits первых 2)` **и** `mean(s первых 2) − mean(s последних 2) ≥ 0.15`.

### Таблицы

- **`gorbov`**, L_norm 12.
  - Задания идут циклом: `black_up` → `red_down` → `alternate` → …
  - `timeLimitMs = round(max(15000, 120000·0.92^L) · (task === 'alternate' ? 1.6 : 1))`.
  - `reshuffleEvery = L < 15 ? null : max(1, 10 − floor((L − 15)/2))` — через сколько верных кликов клетки перемешиваются.
- **`schulte`**, L_norm 6.
  - `size = min(9, 5 + floor(L/8))`.
  - `timeLimitMs = round(max(size²·400, size²·2400·0.93^(L − 8·(size − 5))))`.
  - `reshuffleEvery = null`.
- **Таблица Горбова:** 49 клеток в сетке 7×7 — красные 1..25 и чёрные 1..24, порядок перемешан.
- **Последовательности:**
  - `black_up`: чёрные 1→24;
  - `red_down`: красные 25→1;
  - `alternate`: ч1, к25, ч2, к24, …, ч24, к2, к1 (49 шагов).
- **Балл прогона:** `s = max(0, correctBeforeDeadline − errors) / total`, где `errors` — клики не по той клетке до дедлайна.
- **Метрики Горбова по трём прогонам** (секунды): `V = (t1 + t2)/2`, `P = t3`, `Π = t3 − (t1 + t2)`.

### Числовые ряды

- Рейтинг Эло по семействам: стартовый `R0 = 1000`; K = 48 при `n < 20`, иначе 32.
- `targetD = R − 400·log10(3)` — это даёт P ≈ 0,75.
- Блок — 10 задач. Лимит на задачу — 40 000 мс.
- Выбор семейства: веса `w_i = 1 + (maxR − R_i)/200`.

  | `alt` | 6 | — |
  | `fib` | 4 | перебор `k ∈ {1,2}`, `c` вычисляется |

### Индекс готовности (§7.5)

- **Опубликованные полосы**, кусочно-линейно, значения за краями обрезаются до крайних баллов. Точки (значение → балл):

  | Показатель | Точки |
  |---|---|
  | Горбов V (с) | (29→100), (37→80), (50→60), (60→40), (70→20) |
  | Горбов P = t3 (с) | (43→100), (56→80), (86→60), (106→40), (126→20) |
  | Горбов Π (с) | (9→100), (17→80), (31→60), (40→40), (49→20) |

- **От собственной базы** `v0` (значение из первой диагностики, `v0 = max(v0, 1)`), результат обрезается до [0, 100]:
  - если меньше — лучше: `60 + 40·(v0 − v)/(0.25·v0)`;
  - если больше — лучше: `60 + 40·(v − v0)/(0.25·v0)`.
- **Способности:**

  | Способность | Из чего считается |
  |---|---|
  | `reaction` | среднее баллов: pzmr medianRt ↓, szmr medianRt ↓, rdo meanAbsErrorMs ↓ |
  | `attention` | среднее баллов: Горбов V, gonogo score ↑ |
  | `switching` | Горбов Π |
  | `logic` | numseries correct ↑ |
  | `memory` | `null` (появится в W2) |

- Общий индекс — среднее доступных способностей.

### Сессия W1 (§7.1)

- **Сегменты по порядку:**
  1. `pzmr` 2 мин (разминка);
  2. два из `szmr`, `gonogo`, `rdo` с наибольшим приоритетом, по 5 мин; при равенстве порядок szmr, gonogo, rdo;
  3. `gorbov` 6 мин;
  4. `schulte` 4 мин;
  5. `numseries` 10 мин.
- **Новый блок** начинается, только если время сегмента ещё не вышло. Текущий блок всегда доигрывается.
- **Приоритет** = `min(daysSince, 7)/7 + clamp(1 − L_saved/L_norm, 0, 1) + (plateau ? 0.5 : 0)`. Для модуля без истории `daysSince = 7`.
- **Свободная тренировка** — один сегмент выбранного модуля на 5 мин.

  export interface TrialResult { idx: number; outcome: Outcome; success: boolean; rtMs: number | null;
    errorMs: number | null; key: InputKey | null; frameDropped: boolean; practice: boolean }
  export function resolveBlock(specs: readonly TrialSpec[], tl: BlockTimeline): TrialResult[];
  export interface ReactionSummary { n: number; score: number; meanRt: number | null; medianRt: number | null;

    meanSignedErrorMs: number | null; timingUnreliable: boolean }

- **Правила `resolveBlock`.** Это контракт, тесты проверяют каждый пункт.
  1. Нажатия сортируются по `ts`. Нажатие относится к последнему испытанию `i`, у которого `onset_i ≤ ts`. Нажатия до `onset_0` помечают испытание 0 как фальстарт.
  2. Если `ts ≤ onset_i + windowMs_i` и у `i` ещё нет ответа, это ответ испытания `i`. Повторные нажатия в том же окне игнорируются.
  3. Если `ts > onset_i + windowMs_i`, нужно смотреть на тип испытания `i`:
     - если `i` типа `press` и без ответа, это `late` для `i`, RT записывается;
     - иначе нажатие помечает испытание `i+1` как фальстарт (если `i+1` существует).
  4. Исходы:
     - испытание с меткой фальстарта → `false_start`;
     - `press`: RT < 100 → `false_start`; клавиша совпала → `hit`, иначе `wrong`; ответа нет → `late` (если было) или `miss`;
     - `withhold`: ответ в окне → `commission`, иначе `correct_reject`;
     - `timed`: RT < 100 → `false_start`; клавиша не та → `wrong`; `err = rt − targetOffsetMs`; `|err| ≤ tol` → `hit`; `err < −tol` → `early`; `err > tol` → `timing_late`; ответа нет → `miss`.
  5. `success` ⇔ исход `hit` или `correct_reject`.
- **Правила `summarize`.**
  - Пробные испытания (`practice`) исключаются из всего.
  - `score` = доля `success`.
  - RT-статистика считается по `hit` типа `press`.
  - `errorMs`-статистика — по всем `timed` с ответом.
  - `timingUnreliable` = доля `frameDropped` > 0.05.
  - Пустой набор → `score 0`, статистика `null`.

  - `late press after window counts as late for unanswered press trial`;
  - `press in ISI after answered trial marks next trial false start`;
