# Тренажёр отбора — W2 (0.2.0): план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Версия 0.2.0: исправления 0.1.1, рычаг времени для числовых рядов, модули «Помехоустойчивость», «Струп», «Переключение правил», «Память», звуковые помехи в наушниках, фазы и полный планировщик с финишером, расширенная диагностика и индекс готовности, восстановление данных из файла экспорта. Облачная синхронизация (§8.2) отложена решением пользователя (П9).

**Architecture:**
- Всё, что можно посчитать без DOM, остаётся чистым TypeScript в `src/engine` и `src/modules`: параметры уровней, генераторы, визуальный шум, синтез звука (массив отсчётов), фазы, планировщик, формулы готовности.
- `src/runtime` получает три новых умения: подсказку правила до стимула (cue), фоновый слой (шум, мерцание) с покадровой анимацией и Web Audio-плеер заранее синтезированных буферов. Время предъявления и ответа считается как в W1.
- Новые реакционные модули (Струп, переключение, помехоустойчивость) идут через `ReactionModule` и `ReactionBlockRunner`. Память — отдельный вид блока со своим показом по кадрам и экраном ответа.
- Восстановление — слой в `src/data`: файл, сохранённый «Экспортом данных», проверяется целиком до первой записи, затем строки добавляются по UUID (уже имеющиеся пропускаются), каждый блок с испытаниями и задачами — одной транзакцией. Перед записью делается резервная копия базы.

**Tech Stack:** без изменений относительно W1 (`docs/superpowers/plans/2026-10-14-w1-mvp.md`, раздел Tech Stack). Новых npm-пакетов и crates нет: звук синтезируется своим кодом, восстановление использует обычный `<input type="file">` и существующий crate `backup`.

**Spec:** `docs/superpowers/specs/2026-10-14-trainer-design.md` (дальше — «спека», ссылки вида §5). Исследование тестов: `stress-notes/20_Domain/Test_Battery_Research.md`. Решения W1: `stress-notes/30_Tech/W1_Build_Ledger.md` (правила R1–R40), карта кода: `stress-notes/30_Tech/Codebase_Map.md`.

## Review Focus

1. **Буквы в «Памяти» при английской раскладке.** Пользователь видит «В», жмёт клавишу с «В», а система отдаёт `d`. Тест — Task 9 (`letterFromKey maps physical keys on an English layout`, `digitFromKey accepts top row and numpad`).
2. **Звук недоступен или заблокирован** (нет устройства, `AudioContext` в состоянии `suspended`, громкость 0). Ожидание: блок идёт без звука, ничего не падает, в итогах блока строка «Звук не воспроизводился», уровень меняется по видимой части задания. Тест — Task 7 (`prepare returns null without Web Audio`, `start returns false when the context is not running`) и Task 8 (`plays the block without sound when the context cannot start`).
3. **Обновление с 0.1.0 на 0.2.0 у существующего пользователя.** Ожидание: миграция 0002 применяется к базе с данными W1; старые задачи рядов читаются с лимитом 40 000 мс, рейтинги после пересчёта те же; файл экспорта 0.1.0 (без `timeLimitMs`) восстанавливается; фаза и план для пользователя с 20 днями истории и четырьмя новыми модулями объяснены на главной. Тесты — Task 4 (`W1 database upgrades`, `rebuild gives W1 ratings for rows without a limit`, Rust `upgrades_a_0_1_0_database`), Task 13 (`a 0.1.0 export without timeLimitMs reads as null`), Task 11 (`calibration of new modules after an upgrade`).
4. **Восстановление из повреждённого, чужого или уже загруженного файла; сбой посреди записи.** Ожидание: файл проверяется целиком до первой записи, при ошибке ничего не пишется и видна понятная причина; повторное восстановление ничего не добавляет; при сбое на блоке N блоки до N остаются целыми, от блока N — ничего; без резервной копии восстановление не начинается. Тесты — Task 13 (`a bundle with a broken row writes nothing`, `re-import is a no-op`, `a failure in block N keeps blocks before N whole and nothing of block N`), Task 14 (`a failed backup stops the restore before any write`, e2e `restoring the same file twice adds nothing`).
5. **Дата теста в прошлом, сегодня или изменена.** Ожидание: прошедшая дата не держит фазу «Подводка», в день теста фаза «Подводка», смена даты сразу меняет фазу и план. Тест — Task 11 (`past test date is ignored`, `test day is taper`, `clearing the date falls back to the day-60 rule`).

## Справочник параметров (решения, на которые ссылаются задачи)

### R37: номинальный кадр блока

- `MIN_FRAME_SAMPLES = 10`.
- Раннер собирает дельты всех кадров блока (от первого кадра после `start()` до конца).
- Номинальный кадр блока `frameMs` — медиана этих дельт; если дельт меньше 10, берётся `nominalFrameMs` из опций.
- `droppedOnset[i] = isDroppedFrame(дельта кадра онсета i, frameMs)`. Считается в конце блока; у самого первого кадра дельты нет → `false`.
- Упреждение РДО для испытания `i`: `presentationLeadMs`, если он задан явно; иначе медиана дельт до онсета `i` (если их ≥ 10), иначе `nominalFrameMs`.
- `frameMs` уходит в `BlockTimeline.frameMs` и в `summaryJson` реакционного блока.

### R36: рычаг времени в числовых рядах

- `BASE_ITEM_LIMIT_MS = 40000`, `MIN_ITEM_LIMIT_MS = 8000`.
- Эффективная сложность: `D_eff = D_struct + 200·log2(40000 / limitMs)`.
- Структурный максимум семейства `STRUCT_D_MAX` (проверено перебором 60 000 кандидатов на семейство и разбором диапазонов генерации 2026-10-14):

  | arith | geom | second | alt | fib | linrec | powers | opcycle |
  |---|---|---|---|---|---|---|---|
  | 950 | 1300 | 1300 | 1200 | 1350 | 1650 | 1500 | 1700 |

- Лимит задачи: если `targetD ≤ STRUCT_D_MAX[family]` — 40 000. Иначе `clamp(round(40000·2^(−(targetD − D_struct)/200) / 100)·100, 8000, 40000)`, где `D_struct` — сложность уже выбранной задачи.
- Рейтинг обновляется с `D_eff` от сохранённого лимита. Успех — `correct && timeMs ≤ limitMs`.
- Старые строки (`time_limit_ms IS NULL`) читаются как 40 000.
- Диагностические задачи: `timeLimitMs = null` (действует общий лимит, рейтинги не меняются, R19).
- Потолок с рычагом: `STRUCT_D_MAX + 464` (например, arith 1414 вместо 950). См. решение П3.

### Условия испытаний и разности

- `TrialCond = 'congruent' | 'incongruent' | 'quiet' | 'noisy' | 'repeat' | 'switch'`. Лежит в `TrialSpec.cond`, сохраняется вместе со спецификацией.
- `conditionStats` по условию:
  - `n` — непробные испытания с этим условием;
  - `errors = n − успехи`;
  - `medianRt` — медиана RT попаданий типа `press` без пропущенного кадра онсета; `null`, если таких RT меньше `MIN_COND_RTS = 3`.
- Разность: `condCost(stats, slow, fast) = medianRt(slow) − medianRt(fast)`; `null`, если любая медиана `null`.
  - Помехоустойчивость: `noisy − quiet`.
  - Струп: `incongruent − congruent` (интерференция).
  - Переключение: `switch − repeat` (цена переключения).

- Режим: `L < 20` → `simple` (красный круг, 1 клавиша); `L ≥ 20` → `choice` (красный круг → клавиша 0, зелёный круг → клавиша 1). Стимулы рисуются в центре, как в ПЗМР. ISI `[500, 2500]`.

**Переключение правил (`taskswitch`)**
- Стимул: цвет `red | blue`, форма `circle | square`, размер `large | small` (0,18 и 0,09 меньшей стороны). Все признаки независимы и равновероятны.
- Правила: `L < 20` → `color, shape`; `L ≥ 20` → `+ size`. Соответствие: красный / круг / большой → клавиша 0, синий / квадрат / маленький → клавиша 1. `keyCount = 2`.

- Точки: L = 0 → окно 2000, подсказка 900, смена 0,2; L = 5 → 1369, 475, 0,3; L = 10 → 954, 251, 0,4; L = 20 → 499, 70, 0,5, три правила.

### Визуальный шум (`src/engine/noise.ts`)

- Координаты в «единицах стороны»: меньшая сторона холста = 1, центр — (0, 0). `box = { halfW, halfH }`.
- Фигура `j ∈ [0, distractors)` живёт слотами длиной `lifetimeMs` со сдвигом фазы `j·lifetimeMs/distractors`: `slot = floor((elapsedMs + сдвиг) / lifetimeMs)`.
- Свойства фигуры берутся из `createRng(deriveSeed(seed, j + ':' + slot))`:
  - диаметр `size ∈ [0.06, 0.10]`;
  - центр внутри `box` с отступом `size/2` и на расстоянии ≥ `NOISE_EXCLUSION_RADIUS + size/2` от (0, 0), где `NOISE_EXCLUSION_RADIUS = 0.2` (фигура целиком вне центральной зоны);
  - до 20 попыток, затем точка на окружности радиуса 0,2 + size/2 под случайным углом.
- Форма и цвет — равновероятно из разрешённых пар (см. `farOnly`, `forbidden`).
- Мерцание: `flickerOn = flicker && floor(elapsedMs / 250) % 2 === 1` (период 500 мс); фон `#2b2b2b` ↔ `#3a3a3a`.

### Память (`memory`)

- `L_norm = 9` (длина 7 — средний объём 7 ± 2, ориентир).
- `length(L) = 4 + floor(L/3)`; `itemMs(L) = round(max(300, 1000·0.95^L))`; `gapMs(L) = round(max(100, 250·0.95^L))`; `cardMs = length·itemMs`.
- Режим блока циклом по индексу блока в сегменте: `digits` → `positions` → `card` → `letters`.
  - `digits` — цифры 0–9 по одной;
  - `letters` — 14 согласных `Б В Г Д Ж З К Л М Н П Р С Т` по одной;
  - `positions` — клетки сетки загораются по одной, сторона `max(3, ceil(sqrt(length + 3)))`, клетки без повторов;
  - `card` — все цифры сразу на карточке со стороной `max(3, ceil(sqrt(length)))`, по строкам слева направо, показ `cardMs`.
- В последовательных режимах два одинаковых элемента подряд запрещены.
- Блок — `MEMORY_TRIALS = 6` проб. `s` = доля проб, воспроизведённых точно (весь ряд в порядке). Дополнительно — доля позиций на своих местах. `cvMax = null`.
- Показ: 500 мс знак «+» от первого кадра `t0`. Элемент `k` появляется в первом кадре с `ts ≥ t0 + 500 + k·(itemMs + gapMs)` и скрывается в первом кадре с `ts ≥ онсет + itemMs`. Карточка появляется в `t0 + 500` на `cardMs`.
- Ответ:
  - цифры и буквы — с клавиатуры, Backspace стирает, Enter отправляет;
  - позиции — клик по клеткам, повторный клик по последней снимает её, Enter или кнопка «Готово» отправляет.
- Ввод букв: `e.key` в верхнем регистре, если это буква набора; иначе `e.code` по ЙЦУКЕН: `Comma`→Б, `KeyD`→В, `KeyU`→Г, `KeyL`→Д, `Semicolon`→Ж, `KeyP`→З, `KeyR`→К, `KeyK`→Л, `KeyV`→М, `KeyY`→Н, `KeyG`→П, `KeyH`→Р, `KeyC`→С, `KeyN`→Т.
- Ввод цифр: `e.key` 0–9 или `e.code` `DigitN` / `NumpadN`.
- Точки: L = 0 → 4, 1000, 250; L = 9 → 7, 630, 158; L = 15 → 9, 463, 116; L = 24 → 12, 300, 100.
- Диагностика — протокол объёма: только `digits`, 1000 / 250 мс. Длины 3…12, по 2 пробы на длину (20 проб). Стоп, если обе пробы одной длины неверны. `span` — наибольшая длина хотя бы с одной точной пробой (0, если таких нет).

### Звуковые помехи (`src/engine/audio`)

- Моно, `STRESSOR_SAMPLE_RATE = 22050`, петля `STRESSOR_LOOP_S = 20` с; последние 50 мс плавно сводятся с первыми 50 мс (без щелчка на стыке). Пик ≤ 0,9 (общая нормировка, если сумма слоёв больше).
- Слои (`StressorLayer`, канонический порядок `hum, beeps, metronome, babble`):
  - `hum` («гул кабинета»): розовый шум (фильтр Пола Келлета) + коричневый шум (интегрированный белый с утечкой 0,02) в пропорции 1 : 0,5; RMS 0,1.
  - `beeps`: синус `hz ∈ {700, 1000, 1400, 1900}`, длительность `rng.int(60, 160)` мс, фронты 8 мс (приподнятый косинус), интервал между началами `rng.int(400, 2600)` мс; пик 0,35.
  - `metronome`: период `P = rng.int(550, 850)` мс; щелчок — 2000 Гц, 12 мс, спад с τ = 3 мс; 10 % ударов пропущены, 10 % удвоены (лишний удар через `P/2`); пик 0,3.
  - `babble`: 4 «голоса»; каждый — розовый шум через полосовой biquad (центр `rng.int(400, 1200)` Гц, Q = 1). Огибающая из «слогов» `rng.int(120, 280)` мс с амплитудой `[0.3, 1.0]` и приподнятым косинусом; после 20 % слогов пауза `rng.int(150, 500)` мс. Сумма / 4, RMS 0,08.
- Громкость на выходе: `volume (настройка 0–100 %, по умолчанию 60) / 100 × params.gain`. Включение и выключение — `gain.setTargetAtTime(цель, ctx.currentTime, 0.015)`.
- Старт петли: `source.start(ctx.currentTime + 0.05, offsetS)`, `offsetS = (seed % 20000)/1000`.
- Кэш буферов — по ключу `слои + зерно`, не больше 4.
- Финишер и перегрузка: `FINISHER_AUDIO = { layers: ['hum', 'beeps', 'babble'], gain: 0.8 }`. Объединение со звуком модуля — `mergeAudio`: объединение слоёв, максимум `gain`.

### Перегрузка: финишер и плато (§6.3, §7.1)

- `OVERLOAD_LEVEL_STEP = 3`.
- Сегмент `overload: 'finisher'`: уровень старта `L_saved + 3`; все блоки — перегрузка.
- Сегмент `overload: 'mix'` (модуль на плато): блоки с нечётным индексом — перегрузка на `L + 3` от текущего уровня сегмента, чётные — обычные.
- Блок перегрузки:
  - флаг `overload`;
  - у реакционного модуля звук `mergeAudio(звук модуля, FINISHER_AUDIO)`, `gate: 'all'`;
  - инструкция начинается с «Блок с перегрузкой: уровень на 3 выше обычного.»;
  - не участвует в `L_saved` (как `fatigued`), в усталости и в правиле `g = 2`;
  - учитывается в `lifetimeBlocks` и `lastTrainedAt`;
  - не меняет текущий уровень модуля в сессии. В финишере меняется только уровень самого сегмента финишера.

### Фазы (§7.2)

- `dayNumber = daysBetween(первая сессия любого вида, сегодня) + 1`; без сессий — 1.
- `daysToTest = signedDaysBetween(сегодня, дата теста)`; отрицательное значение = даты нет.
- Порядок проверки:
  1. `daysToTest ∈ [0, 9]` → `taper` (причина `taper`).
  2. `daysToTest ∈ [10, 28]` → `overload` (`test_soon`).
  3. Даты нет и `dayNumber ≥ 60` → `overload` (`day_60`).
  4. `dayNumber ≤ 14` → `base` (`first_days`).
  5. Есть модуль с `lifetimeBlocks < 3` → `base` (`calibration`, список модулей).
  6. Иначе `development` (`weak_spots`).

### Индекс готовности W2 (§7.5)

- Способности:

  | Способность | Из чего считается |
  |---|---|
  | `reaction` | среднее: pzmr medianRt ↓, szmr medianRt ↓, rdo meanAbsErrorMs ↓ (как W1), `diffScore(pomehDeltaMs, 40)` |
  | `attention` | среднее: Горбов V (полосы), gonogo score ↑ (как W1), `diffScore(stroopInterferenceMs, 60)` |
  | `switching` | среднее: Горбов Π (полосы), `diffScore(switchCostMs, 60)` |

### Восстановление из файла экспорта

- Источник — JSON, который пишет `exportBundle` (`src/data/export.ts`): `appVersion`, `exportedAt`, `sessions`, `blocks`, `trials`, `logicItems`, `diagnostics`, `wellbeing`, `settings`.
- Проверка до любой записи (`parseExportBundle`):
  - JSON-объект с массивами `sessions, blocks, trials, logicItems, diagnostics, wellbeing`; `settings` — объект или нет вовсе;
  - каждая строка — поля и типы `src/data/rows.ts`: строки, конечные числа, булевы; `kind` ∈ `SessionKind`, `module` ∈ `MODULE_IDS`, `flags` ⊂ `BlockFlag`, `family` ∈ `FamilyId`, `mood` ∈ 1…5; даты разбираются `Date.parse`, `wellbeing.date` — `YYYY-MM-DD`;
  - `timeLimitMs` у задачи может отсутствовать (файлы 0.1.0) → `null`;
  - лишние поля отбрасываются;
  - `id` не повторяются внутри таблицы; `blocks.sessionId` и `diagnostics.sessionId` есть среди сессий файла, `trials.blockId` и `logicItems.blockId` — среди его блоков;
  - из `settings` берутся только `testDate` (`YYYY-MM-DD` или `null`) и `layout` (`LayoutId`), остальное не читается.
- Сообщение об ошибке — первая найденная:
  - «Файл не читается как JSON.»;
  - «Это не файл экспорта тренажёра: нет списка sessions.»;
  - «Запись blocks[12]: поле score должно быть числом.» (таблица, индекс, поле, что ожидалось);
  - «Запись trials[40]: блок {id} не найден в файле.»;
  - «Запись sessions[3]: id {id} повторяется.»
- Слияние по UUID: строка, чей `id` уже есть локально, пропускается — история только дописывается. Повторное восстановление того же файла ничего не добавляет; восстановление в непустую базу объединяет данные.
- Порядок записи:
  1. сессии — пачками по `IMPORT_CHUNK = 200`, пачка — одна транзакция (`addSessions`);
  2. блоки в порядке файла: блок, его испытания (по `idx`) и задачи — одна транзакция (`addBlock`, в Tauri — `db_batch`); после каждых `YIELD_EVERY_BLOCKS = 20` блоков — пауза `setTimeout(0)` и отчёт о прогрессе, чтобы интерфейс не замирал на месяцах истории (~100 000 испытаний);
  3. контрольные диагностики, затем самочувствие — пачками по 200.
- Первая ошибка записи останавливает восстановление: записанное раньше остаётся (блоки целиком), дальше ничего не пишется. Повторный запуск продолжит с этого места.
- Настройки: локальные не меняются; `testDate` и `layout` из файла записываются, только если локально они ни разу не сохранялись (`storedSettingKeys`).
- Если что-то добавлено (в том числе перед остановкой) — `rebuildCaches`. Главная пересчитывается при возврате на неё.
- Резервная копия перед записью: Tauri-команда `backup_now` выполняет `PRAGMA wal_checkpoint(TRUNCATE)` на пуле plugin-sql и копирует файл базы через crate `backup` (имя `trainer-<stamp>.db`, хранятся 8 новых). В веб-версии файла базы нет, копия не делается. Ошибка копии → восстановление не начинается.

### Решения планировщика (конфликты и пробелы спеки)

- **П1. Разностные показатели в индексе.** Формула W1 `60 + 40·Δ/(0.25·v0)` при `v0` около нуля даёт скачки 0 ↔ 100 от шума. Поэтому для разностей (помехи, интерференция, цена переключения) — та же привязка «первая диагностика = 60», но шаг 40 баллов на фиксированные `40/60/60` мс (≈ 2 стандартные ошибки разности медиан при объёмах диагностики).
- **П2. «Вероятность смены и интервал подсказки сокращаются с L».** Сокращение доли смен облегчило бы задание. План: доля смен растёт до 0,5, интервал «подсказка → стимул» сокращается.
- **П3. Нижний лимит 8 с оставляет потолок** рейтинга числовых рядов (`STRUCT_D_MAX + 464`), но выше прежнего на 464. Сим-тест проверяет рост рейтинга за старый потолок.
- **П4. Фаза «База» не монотонна.** После обновления на 0.2.0 у четырёх новых модулей `lifetimeBlocks = 0`, и фаза возвращается в «Базу» на 1–2 сессии калибровки. На главной причина пишется явно.
- **П5. Подводка.** «2 генеральные репетиции» в W2 — две контрольные диагностики за последние 9 дней (полный «День теста» — W3). Финишера в подводке нет. «Утреннее время» и сон — напоминания на главной. «День теста раз в неделю» в фазе перегрузки — W3. «Длинные прогоны» перегрузки — блоки реакции по 6 мин.
- **П6. Плато.** «Вариант модуля, усиленное чередование, подмешанная перегрузка» = сегмент `mix`: обычный блок и блок перегрузки (L + 3, звук) по очереди.
- **П7. Память** получает четвёртый режим `card`: карточка 3×3, как в методике из исследования, в дополнение к цифрам, буквам и позициям.
- **П8. Новые сегменты диагностики идут после числовых рядов**, чтобы у тестов W1 не изменились ни порядок, ни нагрузка перед ними. Диагностика удлиняется примерно на 9 минут.
- **П9. Облачная синхронизация (§8.2) отложена** решением пользователя 2026-10-14: лимит бесплатных проектов Supabase, существующие проекты не трогать. В W2 её заменяет восстановление из файла экспорта: перенос на новый компьютер и восстановление после переустановки делаются вручную через «Экспорт данных» и «Восстановить из файла экспорта». Очередь синхронизации и зависимость от Supabase не добавляются.
